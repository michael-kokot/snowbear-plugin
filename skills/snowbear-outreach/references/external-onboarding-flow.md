## Onboarding in an external agent
- Use GET /me for the authenticated user's identity, selection version, enrichment status, saved professional background, timezone, LinkedIn connection and sending eligibility. Use that background to personalize the conversation and suggest relevant options; goals remain the user's choice. For an already onboarded account, reuse its context without restarting identity confirmation. When identity is confirmed but enrichment is pending, explain the pending state without repeating confirmation or claiming completion. For an unconfirmed identity, present the returned candidates or ask for the missing personal LinkedIn URL. Only after the user chooses, use POST /me/linkedin with the exact option_number and presentation_version, or their supplied URL. Rejecting candidates also uses the current presentation version. Confirmation requires write access; identity completion and LinkedIn reconnection do not block unrelated permitted reads. Successful matching enrichment completes external identity onboarding silently. Preserve existing conversation context; ask only for missing information. Identity completion does not require choosing a goal, list, campaign or alerts.
- Offer help finding companies, roles or hires that meet the user's needs. For job seekers, first establish and validate the opening and its actual employer; for sales, first establish the company and buyer role. Find suitable opportunities with SnowBear or your own research tools when those targets are missing. Once a target exists, use GET /companies?domain= or q= to look up its saved ID without provider work (or reuse a known saved ID), then show GET /companies/{company_id}/warm-connections immediately, explaining each saved path and why it may help. Then use existing warm searches for further discovery. Shared schools/employers work without LinkedIn authentication; shared background does not establish acquaintance. Preserve the stated relationship owner. Optional LinkedIn network searches use existing allowances and need a covering request. General onboarding and hiring do not automatically trigger warm searches. In later job-search conversations, use SnowBear to fetch/validate job URLs, confirm employers, find warm paths, and preview relevant outreach.
- Default tracking to choosing or creating a list, then POST /lists/{list_id}/columns for fields like that list's Status. Use POST /contacts/columns for reusable facts like Preferred name. Scope and type are immutable; each list field has a distinct column ID, so same-name statuses in separate lists remain independent. Displaying a shared field does not copy values, and creating/displaying a field does not enable personalization. PATCH /contacts/columns/{column_id} edits names/options; retain stable IDs for retained options. POST /contacts/columns/{column_id}/values sets/clears at most 25 exact contact-copy IDs and returns per-item results. List writes require current membership and permission. Preserve list labels and contact-copy IDs when multiple values are returned. Use paged stored reads for browsing and analysis, following every next_cursor including empty intermediate pages. For a downloadable export use POST /contact-exports, then GET /contact-exports/{export_id}; normal lists follow actual membership and requested filters independently of referral-page and native campaign eligibility decisions. Select shared and list-specific fields by stable column ID. Exports authorize no enrichment, provider refresh or outreach change.
- During onboarding, or when the user asks for next-step recommendations after an initial prospect search, use the established goal and target audience to offer relevant options: ongoing weekday discovery through a campaign, or conversation review, drafting and requested outreach to selected people. Present relevant choices simply, personalized to the conversation, with one short sentence per option. Research alone does not authorize drafting, sending, campaign changes or increased sending volume. Introduce campaign settings and approval requirements only after the user chooses campaign setup. Until that choice, do not list daily counts, approval modes, sequence choices or activation settings, or add a starter campaign proposal. Keep lists, enrichment and warm-path work inside the selected path when useful. Continue an already chosen or authorized task instead of asking the user to choose again. Honor research-only requests, connection-only requests and prior declines; identity onboarding does not require choosing either path.
- When the user chooses campaign setup, reuse the targeting already discussed and ask only for missing details. Check saved campaigns and reuse a suitable existing campaign rather than creating a duplicate. For a new campaign, propose three new contacts per weekday with settings.approval_mode:review_all so initial outreach waits for approval. Create paused unless the user's request also authorizes starting it; a saved paused campaign is not running automatic sourcing. Reuse or select a suitable outreach sequence under the existing sequence rules. Optional start/end dates are not prerequisites; use existing defaults when the user has not specified them. Offer explicit sequence_id:null for ongoing sourcing-only research without drafts, enrollments or sends when that matches the user's request. Preserve an existing campaign's settings unless the user authorizes changing them. Campaign sourcing uses SnowBear's weekday schedule; it does not require a separate agent reminder or recurring check-in.
- When the user requests conversation review, drafting or direct outreach, reuse the selected recipients and relevant saved context, including any saved contact_id already supplied. Summarize incoming messages and draft replies only when requested; a request to review or draft does not authorize saving, approval or delivery. Declining a campaign does not decline SnowBear's standalone drafting tools. When drafting is requested, call the available canonical draft_linkedin_message, draft_email or reply tool rather than writing a preview yourself. Standalone drafting needs the saved contact and intent or drafting directions; campaign_id and enrollment_id are optional, so do not require or create a campaign for a standalone preview. Previews work without a connected LinkedIn account. One-off LinkedIn messages and connection requests use send_contact_linkedin_action (POST /contacts/{contact_id}/linkedin-actions), without creating a campaign, after authorization of the authenticated sender, exact recipient, action and final text. Existing clear authorization is sufficient. If LinkedIn is disconnected or needs reconnection, explain that linking it enables SnowBear to send from the user's account. When the user has chosen LinkedIn sending, call POST /linkedin/connect-link using the exposed linkedin_connect_link tool, or the documented REST operation for an HTTP client, and show the secure connection link as the next setup step; A request to send also covers generating this necessary connection link, so do not ask another question just to generate it. For an unconnected account the existing request is POST /linkedin/connect-link with body {}; for reconnect_required, use body {reconnect:true}. Keep the chosen recipient and draft context when the user returns, verify the connection, and continue the authorized task; linking alone never approves a send or enables campaign outreach. Respect paid-plan, connection, quality, hold and allowance checks, reuse the same idempotency_key and exact body on retry, and distinguish queued from confirmed sent. Email previews are available, but email delivery uses existing campaign/sequence operations, not a standalone email-send endpoint.
- Native reports default to settings.report_delivery:snowbear; external_agent suppresses native daily/delayed reports while keeping sourcing. Schedule agent reviews only on explicit recurring authorization, at 10:30 AM local time Monday-Friday, using /me's timezone or asking if unknown. Read GET /campaigns/{id}/review for contacts, sourcing fulfillment, 14-day performance, approvals, blockers, pipeline notes and SnowBear recommendations. For later campaign reviews, show one supported next step and honor prior declines. Underfilled or weak-conversion campaigns should not receive higher-volume recommendations; no sends in sourcing-only campaigns is not weak performance. Draft previews are read-scoped and save/enroll/send nothing.

## Setup progress and account handoff

At setup start, briefly thank the user, acknowledge their request and say you are starting before reading instructions or calling tools. Give short, plain-language updates between setup stages and during noticeable delays when the client supports intermediate messages. After sign-in, acknowledge the user's return and say you are checking access before verification calls; claim verified access only after success. Explain any action needed from the user. Avoid protocol details unless requested or needed to fix a problem. Never invent progress or promise monitoring or timed updates the runtime cannot perform. Keep tool names, API paths and selection/version fields internal in ordinary user-facing updates, headings, checklists and summaries; describe the account check in plain language and perform it yourself. Never ask the user to run get_me. Technical details are appropriate only when requested or needed to resolve a specific error.

During setup or after sign-in, call get_me (HTTP: GET /me) in the intended environment; read_docs alone is insufficient. Confirm the account and use its identity/enrichment state. Ask only for missing identity choices with current selection versions; never repeat confirmed identity. Pending enrichment or LinkedIn reconnection does not block permitted saved reads.

Resume an authorized task. For setup alone, announce and perform a read-only campaign check without asking whether to check, unless declined or explicitly connection only. Use list_campaigns and review_campaign for up to three relevant active or recent campaigns; reuse results and label partial coverage.

Report names/status, sourcing, sends/replies with their time window, approvals and blockers. Distinguish queued from sent, unknown from zero, and failed reads from empty accounts. Sourcing-only campaigns need no sends. LinkedIn reconnection blocks LinkedIn sending, not saved research or drafts; email is separate.

During onboarding or requested next-step recommendations, use the established goal and audience to offer relevant campaign discovery, conversation review, drafting or requested outreach options. Continue an already chosen path and honor research-only requests, connection-only requests and prior declines. For later reviews, suggest one supported next step. This check authorizes no discovery, campaign changes, approvals, sends or recurring work. Skip skill-installation status unless requested. Ordinary calls and token renewal need no repeated welcome.
