## Analyze a saved list and show results as they arrive
Keep contact work on the user's named or already selected list: analysis, filtering, tracking, exports and membership changes should preserve that list and its team. Resolve a missing list with GET /lists; ask only when the intended list or team is ambiguous. "My network" means the user's first-degree list (kind linkedin_connections); "our network" or a named team's network means that team's first-degree list (kind team_linkedin_connections). Check owner/team identity as well as kind, because list names can change. Never silently substitute all saved contacts, another list or personal contacts when the requested list is missing or inaccessible. An explicit request for all saved contacts may use the broader audience. A single-person lookup, profile correction or campaign-specific action keeps its exact requested person or campaign; it does not require creating a list. Preserve each tool's existing permissions, side effects and approval rules.
- Establish the exact list before starting. For "my network", resolve kind linkedin_connections for the user; for "our network", resolve kind team_linkedin_connections for the intended team. Reuse a known list ID from the conversation, or GET /lists and inspect owner/team identity. If the list is ambiguous, ask which list. If missing or inaccessible, explain the blocker; never start an all-saved fallback.
- Start with the chosen list_id and question or criteria. Use all_saved: true only for an explicit request to analyze all saved contacts. criteria_from_campaign_id provides criteria, not a campaign audience. Examples: {"list_id":"<list_id>","question":"mid-level product managers in the US"}; {"all_saved":true,"question":"fintech founders"}; {"from_search_id":"<search_id>","criteria":[{"key":"<kept_key>","label":"Product experience"}]}. A criteria-only preview uses dry_run: true.
- State the returned scope_summary in plain words and show the criteria. Show promising people immediately, High first, with name, role, company, LinkedIn link, per-criterion levels and who knows them on a team. Start returns up to 25 people; follow-up results default to 25 and allow up to 200 per call. Page through every next_cursor needed for the user's requested count; 25 and 200 are page sizes, not search or export limits.
- While complete is false, check results about every 20 seconds when the runtime supports continuing this turn and show strong new matches without repeating people already shown. Follow next_cursor for rows ready now; revisit the first page for newly assessed top matches because order can change. has_more: false does not mean the search is complete. Do not promise background monitoring or timed updates the runtime cannot perform.
- Quote only unique people. Say "420 people assessed; 1,530 loaded so far, with more loading" while progress.loading_contacts is true and total_is_exact is false. progress.total is a lower bound until total_is_exact is true; an exact total can be reported once that flag is true even if assessment or loading is continuing. progress.pending means waiting for assessment. Zero rated with pending/loading means first results are still being prepared, not no matches or a failed search. Unclear means insufficient profile evidence; counts.not_rated means failed assessments. Provisional counts and rankings can change; label them as progress until complete.
- Refine in place with PATCH and the complete criteria list with kept keys; this updates the same Match column. Explain that replacement before editing. For a requested comparison, use from_search_id to create a separate search and Match column; it inherits the full audience unless explicitly replaced. Never start another search merely to poll, retry a status read or request more results. Save only when wanted; saving keeps the Match column available on the searched list, discoverable through that list's column catalog.
